# E. Final E2E certification matrix and acceptance checklist

Current status: **none of these gates is certified by this planning run**. Existing source, historical runtime observations, mocked tests and a complete plan are different evidence classes. A gate is PASS only on the recorded release SHA with the required evidence. Missing evidence is FAIL/BLOCKED for that gate, not implied success.

## Evidence package format

Each gate record contains date/time and timezone; task IDs; branch/SHA/patch hash; Python/package/model/client versions; migration/schema version; local dataset/account scope; fixture/capture hashes; actions and expected effects; observed result IDs/counts; command/proposal/draft/send IDs where relevant; focused/full test outputs and skips; provider/readback evidence where required; limitations; verifier and HUMAN approvals. Never include tokens, client secrets, full bodies or private contact exports in the shareable record.

An HTTP 200 must be checked for the tool envelope and command terminal state. A provider acknowledgement must be checked against actual provider state. Model citations must point to supplied stored evidence; a citation's existence alone does not validate its claim.

## Final operator checklist

- [ ] **Revision:** exact release SHA, dependency versions, schema versions and permitted configuration recorded; no required gate relies on an older incompatible patch.
- [ ] **Data integrity:** consistent backup opens; SQLite integrity and foreign-key checks pass; lead/person/task/source/message/topic relationships reconcile; no destructive migration; legacy records retain stable IDs and evidence.
- [ ] **Source provenance:** discussion/post/capture URLs, authors and timestamps distinguish source time from capture time; contact evidence and Gmail account/message/thread/RFC IDs preserved; missing fields remain unknown.
- [ ] **Identity:** exact unique matches are distinguishable from inference; ambiguous candidates cannot silently overwrite canonical people/companies; verified contact claims have recorded verification evidence.
- [ ] **Idempotence:** duplicate captures/pages/history/candidates/approvals/tasks produce no duplicate domain records. Reanalysis versions have explicit source hashes. Repeated send requests never cause automatic duplicate delivery.
- [ ] **Completeness:** discovered, stored, partial, stale, failed and unavailable records have separate counts; mailbox scope includes explicit Spam/Trash policy; source absence never represented as global negative evidence.
- [ ] **Failure recovery:** crash between fetch/persist/checkpoint resumes safely; research claims/leases recover; failed-item queue actionable; revoked auth isolated; expired history triggers safe catch-up. Model failure does not lose intake.
- [ ] **Account isolation:** all four identities proven; account propagated through threads, drafts, attempts, cursors, UI/tools/MCP and CRM communication views. Explicit multi-account reads label every record; mutating targets always one account.
- [ ] **Model boundaries:** planner, classification and wording outputs validated; reasoning not executable; no SQL/shell/filesystem/network/email tools; malicious source instructions do not select or authorize actions.
- [ ] **MCP:** real consumer initialize/list/call verified, descriptors agree with application schemas; READ allowlist excludes proposal/approval/sync/draft/send; startup/reads do not mutate schema; any audit metadata effects documented and redacted.
- [ ] **Communication authority:** suggested text, local draft, Gmail draft, approved version, send attempt, unknown outcome and provider-confirmed sent state distinct. Full recipients/attachments/account shown before approval; any edit invalidates it.
- [ ] **Delivery recovery:** provider readback confirms sender/thread/message/SENT and controlled recipient result. Unknown attempt is never retried blindly; no claim that a local DB key guarantees remote exactly-once delivery.
- [ ] **Follow-up:** uncertain dates/targets clarified; APP_TIMEZONE recorded; accepted email marker creates one reviewed task with source/account/thread/message/command reference; rejected proposal creates none.
- [ ] **Content:** MIME/charset/attachment/inline cases work within documented size limits; original retained; HTML safe; no automatic remote images; unsupported content produces explicit warnings.
- [ ] **Restart:** app/model/MCP cold start and reconnect work independently. Pending sync/candidate/task/draft/approval/send states survive safely; no replay-induced writes or sends.
- [ ] **Restore:** restore DB plus Knowledge originals and attachment files into a disposable path; counts/hashes/references match. Credential recovery is documented separately and securely.
- [ ] **Security/privacy:** loopback binding, Host/Origin protections, scoped OAuth, token identity checks, atomic token writes and safe secret storage verified. Logs/command summaries do not dump raw bodies/private contact data/credentials by default.
- [ ] **Regression:** targeted and full isolated suite pass on Python 3.11+; no test reaches real DB/Gmail; only explicitly optional PostgreSQL acceptance remains outside scope.
- [ ] **Operational use:** operator can start/stop, select account, ingest/resume/recover, inspect provenance, review/apply a proposal, draft/approve/reconcile and restore using the runbook.
- [ ] **Permission status:** operator capture is the certified Community collection path unless a separately authorized collector is later implemented and verified. “Automated collection not authorized/not implemented” remains visible where applicable.
- [ ] **Final acceptance:** HUMAN records dated acceptance of Gates 1–10 and the exact release manifest. No mandatory limitation is hidden as an optional enhancement.
